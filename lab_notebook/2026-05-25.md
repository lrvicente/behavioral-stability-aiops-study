## Log observations

Transient `first network error` log entries on `cnsm.fault.active` items
continue to appear, but at significantly lower frequency than in the
previous health check (top item now shows 19 occurrences in 2000 log lines,
down from 62 in the previous snapshot). These errors are an expected
artifact of the fault injection process: when a fault is active on a host,
the Zabbix agent on that host becomes transiently unresponsive, which the
server logs as a network error. The agent recovers in the next collection
cycle. This is a documented and expected behavior of the experimental
intervention, not a system fault.

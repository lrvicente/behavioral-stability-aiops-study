## GPU fault injector reconciliation to locked protocol section 5.2 (Sprint S2 prep)

### Context

Sprint S2 (cross-environment GPU fault injection) starts 2026-07-10. Per the
pre-pilot divergence recorded on 2026-06-13, the GPU fault injector still used
three legacy fault classes whose mechanisms did not match the ontology mapping
in EXPERIMENTAL_SETUP.md section 5.2 / 5.2.1, and one mandated class was missing.
This entry documents the reconciliation, validation, and S2 schedule generation
completed today, ahead of the S2 start and before the author is unavailable
(2026-07-09 and 2026-07-10, external events).

### Reconciliation of the six GPU fault classes

Source of truth: EXPERIMENTAL_SETUP.md section 5.2 (mechanism table) and 5.2.1
(cross-environment ontology mapping). Final state of infra/scripts/inject_fault_gpu.py:

- gpu_utilization_spike (compute_saturation): CUDA matmul loop. Unchanged.
- gpu_memory_pressure (memory_pressure): CUDA tensor allocation to fraction. Unchanged.
- disk_io_contention (io_bottleneck): fio randrw 70/30 on the NFS dataset mount.
  Reimplemented (was pcie_bandwidth_sat).
- data_loader_bottleneck (network_degradation): fio high-latency small random
  reads (thinktime) on the dataset mount. Reimplemented (was network_degradation
  via tc netem).
- batch_inference_overload (process_instability): N concurrent resnet50 inference
  processes contending for SM/VRAM. Reimplemented (was cuda_process_kill).
- cpu_contention_during_training (Lambda-only, excluded from paired SHAP):
  stress-ng --cpu on host CPUs during training. New (was absent).

Design decision: the injector runs as a separate cron process and must not
restart the resnet50 training process (which would contaminate the cycle).
IO/loader faults therefore act on the shared NFS dataset mount the DataLoader
reads from; inference overload spawns concurrent CUDA processes. This preserves
the behavioural signature of the mapped OVH class while respecting the
separate-process constraint.

data_loader_bottleneck mechanism: fio-latency selected over tc netem because it
is self-contained (no NIC topology assumptions) and directly realizes the
"artificial latency in data loading pipeline" wording of section 5.2. The netem
branch was evaluated and dropped.

Watchdog: post-fault recovery confirmation now runs for the two disruptive
classes that can destabilize training (gpu_memory_pressure, batch_inference_overload),
replacing the previous (gpu_memory_pressure, cuda_process_kill) pair.

### Validation (cnsm-gpu-01, 2026-07-08)

All six classes validated at 60s each while the resnet50 training workload was
active (heartbeat=1, GPU ~99% util). First pass: gpu_utilization_spike,
gpu_memory_pressure (watchdog recovery OK), batch_inference_overload (watchdog
recovery OK), and cpu_contention_during_training (clean run) passed. The two fio
classes initially failed with a wall-clock timeout because fio paid the NFS
file-creation cost inside the timed window. Fix: persistent layout files
(--unlink=0), fio internal --timeout, generous outer subprocess guard (+180s),
reduced layout sizes, and a one-time pre-layout step. Second pass: both fio
classes completed cleanly (disk_io_contention ~116 MB/s read, p99 ~41ms;
data_loader_bottleneck IOPS ~2102, thinktime latency signature as intended).

### S2 schedule generation

New generator infra/scripts/fault_schedule_gen_gpu.py, mirroring the OVH
generator conventions (deterministic seeded RNG, committed before collection as
pre-registration evidence). 7-column GPU schema. Frequencies per section 5.2:
gpu_utilization_spike 2/day, all others 1/day => 7 events/day * 28 days = 196
events. Non-overlap enforced (min gap 120s configured, 140s minimum produced) so
the injector's "SKIP another fault still active" guard never drops an event.
Determinism confirmed (identical MD5 across two runs, seed 42).

Output: protocols/fault_schedule_lambda_s2.csv (196 events, 2026-07-10 to
2026-08-07). Deployed to cnsm-gpu-01 at /etc/cnsm/fault_schedule_gpu.csv (prior
pre-pilot CSV backed up to fault_schedule_gpu.pre_pilot_backup.csv).

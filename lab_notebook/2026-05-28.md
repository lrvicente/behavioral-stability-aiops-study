## Decision 1 — GPU node (cnsm-gpu-01) brought up during pre-pilot

The protocol (EXPERIMENTAL_SETUP.md §3.2.1) places the Lambda A10 as a monitored
host in Sprint S2 (weeks 9–12). Today, in the pre-pilot window, the A10 was
provisioned, instrumented (Zabbix agent, 15 GPU metrics, ground-truth
UserParameters), given a baseline workload, and a GPU fault injector with 5
classes. See protocols/GPU_NODE_SETUP.md for full detail.

Framing: this is TECHNICAL VALIDATION, not study data collection. Data produced
during the pre-pilot (28–29 May) is for pipeline validation and will NOT enter
the cycle-1 dataset used for training/evaluation. The S2 collection (weeks 9–12)
remains the pre-registered data-collection window. This preserves the zero-shot
cross-environment design (the model must not see GPU data during training).

## Decision 2 — Divergences to reconcile before S2

The pre-pilot tooling diverges from the LOCKED protocol §5.2 and must be
reconciled (or formally amended) BEFORE S2 collection begins:

- Fault class names/mechanisms differ from the pre-registered ontology mapping
  (§5.2.1). Pre-pilot used: gpu_compute_stress, vram_pressure, pcie_bandwidth_sat,
  network_degradation, cuda_process_kill. Protocol specifies: gpu_utilization_spike,
  gpu_memory_pressure, disk_io_contention, data_loader_bottleneck,
  batch_inference_overload (+ cpu_contention_during_training). RQ2/RQ3 depend on
  the ontology mapping, so the S2 classes must follow §5.2.1.
- Workload: pre-pilot used ResNet50 INFERENCE at 50–85% utilization. Protocol
  §4.2 specifies ResNet50 TRAINING loop at 80–95% + batch inference every 30 min.
- Schedule: pre-pilot used pre_pilot_schedule.csv (seed 142, 10 events). Protocol
  §5.2 specifies fault_schedule_lambda_cycle1.csv (seed 42, 28 days, ~200 events).

Action: before S2, align the GPU fault classes to the §5.2.1 ontology mapping,
switch workload to training profile, and generate the pre-registered lambda
schedule. The pre-pilot tooling (infra, monitoring, injection mechanism) is
reusable; the parameters must be brought into protocol compliance.
